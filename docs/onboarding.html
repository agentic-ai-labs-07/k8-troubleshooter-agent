How one run works

You ask a question. The agent loops: the model picks one tool, the tool reads the cluster, the model sees the result. It stops when the model answers or after 8 model calls.

Your questioncli.py
→
Agent loopagent/graph.py (LangGraph)
⇄
Modelllm/: OpenAI, or rules
→
One of 4 toolstools/kubernetes.py
→
kind clusterclients/kubectl.py, limited login
Answercause, evidence, next step
→
You approveapprove ID
→
One port changenot-ready-app only
→
Re-checkfresh evidence

Every step is written to traces/<run_id>.jsonl (OpenTelemetry) and printed live as one log line. The orange boxes are the only write, and only for the not-ready-app scenario.

Demo in two terminals

# terminal 1: create a broken app
docker compose run --rm admin scenario apply crashing-app

# terminal 2: watch it live

# terminal 1: ask the agent (prints each step, then JSON)
docker compose run --rm agent investigate "Why is crashing-app unhealthy?"

# grade the model on all three scenarios (apply all three first)

Reading order

  1. README.md: what you type and what comes back.
  2. src/k8s_troubleshooter/cli.py: the front door. Commands investigate, eval, approve, scenario.
  3. src/k8s_troubleshooter/tools/kubernetes.py: the four tools the model may call.
  4. src/k8s_troubleshooter/safety/: what is allowed, and how secrets are hidden.
  5. scenarios/not-ready-app/manifest.yaml: one planted failure.
  6. src/k8s_troubleshooter/agent/graph.py: the loop and the answer check. Then agent/remediation.py for approve.
  7. src/k8s_troubleshooter/evals/ and tests/: how we know an answer is right.

Files

Under src/k8s_troubleshooter/. React terms in brackets, as a rough guide.

FileWhat it does
cli.pyParses commands, sets up logging, prints JSON. Exit 0 = answer, 1 = an eval failed, 2 = refused or failed. (The screen.)
agent/graph.py, state.py, prompts.py, schemas.pyThe LangGraph loop, what it carries between steps, the system prompt, and the answer shape. (The container component and its state.)
agent/remediation.pySaves a proposal, applies it after approve, and checks again.
llm/provider.py, llm/rule_based.pyPicks the model: OpenAI by default, or the rule-based stand-in with AGENT_MODEL=rules. Another provider is one branch here. (The API client factory.)
clients/kubectl.py, clients/kubernetes.pyThe only place kubectl runs, with fixed arguments and no shell, and the cluster reads plus the one patch. (axios and the API module.)
tools/kubernetes.pyThe four tools the model may call. Every result goes through secret hiding.
safety/guardrails.py, safety/redaction.pyAllowed names, ports, question length, advice, and the one fix; and secret hiding. (Validation middleware.)
observability/tracing.pyOne OpenTelemetry file per run, plus the live log line per step.
evals/scenarios.py, evals/graders.pyThe three scenarios, their expected facts, and the checks. Used by eval and the tests.
config.py, exceptions.pySettings from environment variables, and the two error types.
scenarios/One Kubernetes manifest per failure, each with a healthy neighbor app.
tests/Unit tests on a fake cluster, plus kind tests when both logins exist.
Dockerfile, docker-compose.ymlOne image. Two services: agent (limited login, key as a secret file) and admin (scenarios only).
kind.yaml, rbac.yaml, scripts/setup-access.shThe cluster, the agent's Kubernetes permissions, and the two logins.
.env.exampleSettings to copy into .env: model, key, limits, log level.
.github/workflows/ci.ymlStarts kind, runs the tests, builds the image.

Safety in layers

LayerWhat it stops
Code (tools/, safety/guardrails.py)The model can only call four reads. No shell. Questions over 500 characters are refused. Advice with a command or a destructive word is blocked. The one write needs your approval, must match the live app, and runs once.
Secrets (safety/redaction.py)Every tool result, including events and errors, has secret-looking values replaced with <redacted> before the model or the trace sees it.
Kubernetes (rbac.yaml)The agent's login expires in 1 hour. It may list pods everywhere, read only in the three app namespaces, and patch only not-ready-app. Even buggy code is refused Secrets, delete, exec, and kube-system logs.
Container (Dockerfile, docker-compose.yml)Runs as a non-root user with all Linux capabilities dropped. Base image and CI actions pinned by digest and commit.

Logs and events are untrusted text and can carry planted orders. The prompt says to ignore them, and the layers above hold even if the model obeys. Known limits are listed in the Safety section of README.md.
